## 1. Purpose

Return a `.docx` file's core document properties (title, author, created/modified timestamps) plus a word count, so a calling agent can get provenance and size context about a document without downloading and re-tokenizing its full text itself.

## 2. Input Schema

| Parameter | Type | Required | Description / Value range |
| --- | --- | --- | --- |
| `path` | `str` | yes | Filesystem path to a `.docx` file. Same resolution and sandboxing rules as `read_document` (see [specs/read_document.md §2](read_document.md#2-input-schema)). |

JSON Schema, as actually generated by the MCP SDK from the `path: str` parameter:

```json
{
  "type": "object",
  "properties": {
    "path": { "type": "string" }
  },
  "required": ["path"]
}
```

## 3. Output Schema

Sketch:

```json
{
  "title": "string or null",
  "author": "string or null",
  "created": "string or null - W3CDTF timestamp exactly as stored",
  "modified": "string or null - W3CDTF timestamp exactly as stored",
  "word_count": "integer"
}
```

JSON Schema, generated by the MCP SDK from the `GetMetadataResult` model:

```json
{
  "type": "object",
  "properties": {
    "title": { "type": ["string", "null"] },
    "author": { "type": ["string", "null"] },
    "created": { "type": ["string", "null"] },
    "modified": { "type": ["string", "null"] },
    "word_count": { "type": "integer" }
  },
  "required": ["title", "author", "created", "modified", "word_count"]
}
```

Field semantics:

- **`title`** — `docProps/core.xml`'s `dc:title` text content, or `null` if the part is missing, the element is absent, or the element is present but empty.
- **`author`** — `docProps/core.xml`'s `dc:creator` text content (the document's original author property, as Word itself calls it under File → Info), or `null` under the same conditions as `title`. `cp:lastModifiedBy` (a different, separate property Word also tracks) is **not** surfaced by this tool — out of the scope the Roadmap names ("title, author, created/modified dates, word count").
- **`created`** / **`modified`** — `docProps/core.xml`'s `dcterms:created` / `dcterms:modified` text content, returned **exactly as stored** (typically W3CDTF, e.g. `"2024-01-01T00:00:00Z"`), or `null` under the same conditions as `title`. This tool does not parse, validate, or reformat the timestamp — see [Limitations](#5-limitations-non-goals).
- **`word_count`** — the number of whitespace-delimited tokens (Python `str.split()` semantics) across every top-level body paragraph's plain text (see `document.py`'s shared plain-text helper, [ADR-0003](../../../docs/adr/0003-phase-2-module-layout.md)) and every table cell's plain text, in document order. Paragraphs are joined by `"\n"` before tokenizing (so a word never spans two paragraphs), but *runs within* one paragraph/cell are concatenated with no inserted separator — identical to how `read_document` and `get_structure` assemble text, so a word Word itself split across two `w:r`/`w:t` runs (e.g. by spell-check) is still counted as one word, not two. Heading `"# "` prefixes and inline `"[^N]"` footnote markers are **not** part of the counted text (they are `read_document`'s own rendering convention, never present in the underlying `w:t` content).

## 4. Assumptions and Preconditions

- Same as `read_document`: `path` resolves inside an allowed root; the file is a valid ZIP containing at least `word/document.xml` (required for `word_count`, which does not depend on `docProps/core.xml`).
- `docProps/core.xml` is **not required** to exist — many minimal or non-Word-generated `.docx` files omit it entirely. Its absence degrades `title`/`author`/`created`/`modified` to `null`; it never fails the call, since `word_count` remains computable.

## 5. Limitations (Non-Goals)

- **Timestamps are not parsed or normalized.** `created`/`modified` are returned as the literal string content of `dcterms:created`/`dcterms:modified`, whatever format the producing application wrote (almost always W3CDTF/ISO 8601, but this tool does not validate that). A caller that needs a parsed `datetime` must parse the string itself.
- **Only four core properties are surfaced.** `docProps/core.xml` can carry more (`cp:lastModifiedBy`, `cp:revision`, `cp:category`, `dc:subject`, ...) and `docProps/app.xml` carries application-specific statistics (page count, character count, company, manager, ...) — none of these are read by this tool. This is a deliberate scope boundary, not an oversight: the Roadmap names exactly title/author/created/modified/word-count, and reading more than that widens what a calling agent's context window (and any downstream system it forwards results to) is exposed to for properties nobody asked for.
- **`word_count` is a whitespace-token count, not a linguistic word count.** Text without inter-word whitespace (e.g. contiguous CJK or Thai script) is undercounted — a contiguous run of such characters counts as one token, not as the number of words a native reader would perceive. This is the same class of limitation `read_document` already accepts for text extraction generally; no per-script tokenization is implemented.
- **Table-of-contents / navigation-pane "page count" is not computed** (`get_structure` covers structural navigation; page layout is not something this project computes at all, since docx-mcp never renders the document).

## 6. Formatting & Safety Guarantees

- Read-only, same as `read_document`.
- `path` resolved and validated against the allow-listed roots, and a UNC network path rejected, before the file is opened — identical to [specs/read_document.md §6](read_document.md#6-formatting--safety-guarantees).
- `word/document.xml` **and, if present, `docProps/core.xml`** are parsed with the same hardened `lxml` parser as every other part this project reads (`resolve_entities=False`, `no_network=True`) — see [ADR-0001](../../../docs/adr/0001-ooxml-library-and-module-layout.md), [ADR-0003](../../../docs/adr/0003-phase-2-module-layout.md).
- No property value is logged (see [docs/documentation-standards.md §6](../../../docs/documentation-standards.md#6-logging-and-observability-baseline): "no secrets and no document content in the log" — `title`/`author` are document content, not diagnostic data).

## 7. Error Behavior

| Case | Behavior |
| --- | --- |
| `path` escapes all allowed roots / no allowed roots configured / UNC network path | Identical to `read_document` (see [specs/read_document.md §7](read_document.md#7-error-behavior)). |
| File does not exist, is not a file, is not a valid ZIP, exceeds the size limit, or is missing/malformed `word/document.xml` | Identical to `read_document` — these checks are shared, unchanged logic. |
| `docProps/core.xml` is missing | Not an error — `title`, `author`, `created`, `modified` are all `null`; `word_count` is still computed. |
| `docProps/core.xml` is present but malformed XML | **Degrades to `null` for all four properties rather than failing the call** — unlike a malformed `word/document.xml` (a hard error, since the whole tool's output depends on it), a broken *optional* metadata part must not block a caller that only needs `word_count`, or that is calling `get_metadata` as one of several tools against a document it can still `read_document` successfully. This asymmetry is deliberate and documented here precisely so it isn't later "fixed" into an inconsistency with `get_structure`'s handling of a malformed `word/styles.xml` (which *is* a hard error, since `word/styles.xml`, once declared, is expected to be well-formed the same way `word/document.xml` is) — see [specs/get_structure.md §7](get_structure.md#7-error-behavior) for the contrast. |
| `dc:title` / `dc:creator` / `dcterms:created` / `dcterms:modified` individually absent or empty | That field is `null`; the other fields and `word_count` are unaffected. |
| `docProps/core.xml` contains a DTD declaring an external entity | Parsed successfully; the entity reference is never resolved (same guarantee as `word/document.xml`). |

## 8. Test Coverage

Reference: `tests/test_metadata.py` (functional and error/edge at the `get_document_metadata` level, including XXE hardening for `core.xml`), `tests/test_get_metadata_tool.py` (contract, functional, error/edge at the MCP-protocol level), `tests/test_security.py` (path sandboxing, shared), `tests/integration/test_read_document_and_get_structure_consistency.py` (cross-checks `word_count` against `get_structure`'s independently-assembled paragraph text).

- **Contract:** tool discoverable via `list_tools`; name, description, input schema, output schema, and version (`_meta`) match this spec.
- **Functional:** against `tests/fixtures/structured.docx` (deterministic title/author/created/modified core properties set at fixture-generation time) for metadata; word count checked against both `structured.docx` (includes table-cell text) and `minimal.docx` (plain-paragraph baseline, including the run-split-safe tokenization rule and, incidentally, python-docx's own bundled-template author/date defaults when a fixture never explicitly sets them).
- **Error/edge:** path outside allowed roots; oversized file rejected before parsing, file at exactly the size limit accepted; missing `docProps/core.xml` (all four properties `null`, `word_count` still correct); malformed `docProps/core.xml` (degrades to `null`s, does not raise); empty `dc:title`/`dc:creator` elements (`null`, not `""`); `cp:lastModifiedBy` never surfacing as `author`; unicode and astral characters in `title`/`author` round-trip correctly; XML-predefined-entity escaping (`&amp;`/`&lt;`/`&gt;`) in property text decodes normally; word count excludes `read_document`'s own markers and does not split a word across runs; XXE-crafted `docProps/core.xml` (external entity not resolved).
