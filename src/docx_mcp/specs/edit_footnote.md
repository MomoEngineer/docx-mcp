| Field | Value |
| --- | --- |
| **Tool name** | `edit_footnote` |
| **Version** | `1.0.0` |
| **Type** | Write |

## 1. Purpose

Update an existing footnote's content in a `.docx` file, addressed by the id `get_footnotes` reports, without touching its anchor in the body text or its id — so the calling agent can fix or rewrite a footnote's text without re-attaching it.

## 2. Input Schema

| Parameter | Type | Required | Description / Value range |
| --- | --- | --- | --- |
| `path` | `str` | yes | Filesystem path to a `.docx` file. Same resolution and sandboxing rules as every other tool. |
| `footnote_id` | `str` | yes | The `w:id` of the footnote to edit, as reported by `get_footnotes`/`get_structure`/`add_footnote`. Must not be `"-1"` or `"0"` (Word's reserved boilerplate ids). |
| `content` | `str` | yes | The footnote's new text content. May be empty. A `"\n"` inside it starts a new paragraph within the footnote, same convention as `add_footnote`. |
| `expected_content` | `str \| null` | no | If given, must equal the footnote's current content (as `get_footnotes` would report it) exactly, or the call fails as stale instead of overwriting. `null`/omitted (default) skips this check. |

JSON Schema, as generated by the MCP SDK:

```json
{
  "type": "object",
  "properties": {
    "path": { "type": "string" },
    "footnote_id": { "type": "string" },
    "content": { "type": "string" },
    "expected_content": { "type": ["string", "null"], "default": null }
  },
  "required": ["path", "footnote_id", "content"]
}
```

## 3. Output Schema

Sketch:

```json
{ "previous_content": "The old footnote text." }
```

JSON Schema, generated from the `EditFootnoteResult` model:

```json
{
  "type": "object",
  "properties": {
    "previous_content": { "type": "string" }
  },
  "required": ["previous_content"]
}
```

Field semantics:

- **`previous_content`** — the footnote's content exactly as `get_footnotes` would have reported it immediately before this call overwrote it (never `null`: unlike `get_footnotes`' own `content` field, which can be `null` for a dangling anchor with no declared footnote, `edit_footnote` only ever succeeds against a footnote that is already declared in `word/footnotes.xml`, so its content is always resolvable, possibly as an empty string).
- **Content model**: `content.split("\n")` replaces the footnote's existing `w:p` children entirely — one fresh `w:p` per line, the first one prefixed with the standard auto-number reference run (`w:r/w:rPr/w:rStyle w:val="FootnoteReference"` + `w:footnoteRef`). This is the exact inverse of `get_footnotes`' `"\n".join(...)` reading convention (see [specs/get_footnotes.md §3](get_footnotes.md#3-output-schema)), so a round-trip through `get_footnotes` after this call reproduces `content` verbatim. **Any run- or paragraph-level formatting the old content had (bold, italic, multiple runs, etc.) is discarded**, not preserved — see [ADR-0007 §Decision.6](../../../docs/adr/0007-phase-6-footnote-edit-module-layout-and-multi-part-atomic-write.md) for why a `replace_text`-style formatting-preserving substitution was rejected here.
- **Anchor and id are untouched.** Only the target `<w:footnote>`'s children change; its `@w:id` attribute, and every `w:footnoteReference` anywhere in `word/document.xml`, are byte-for-byte unaffected.

## 4. Assumptions and Preconditions

- Same as every write tool: `path` resolves inside an allowed root, checked before the file is opened.
- `word/footnotes.xml` must already exist and already declare a `<w:footnote>` with the given `footnote_id` — unlike `add_footnote`, this tool never creates package parts.

## 5. Limitations (Non-Goals)

- **Existing run/paragraph-level formatting inside the footnote is not preserved.** See [Output Schema](#3-output-schema); this is a deliberate content-model choice, not a bug.
- **Cannot create a new footnote.** Use `add_footnote` for that; `edit_footnote` fails if `footnote_id` is not already declared.
- **Cannot edit Word's boilerplate separator/continuationSeparator footnotes** (`footnote_id` `"-1"`/`"0"`) — see [Error Behavior](#7-error-behavior).
- **Cannot re-anchor a footnote to a different paragraph, or change its id** — `word/document.xml` is never touched by this tool.
- **Endnotes are not supported** — same footnotes-only scope as the rest of this tool surface.

## 6. Formatting & Safety Guarantees

- `path` is resolved and validated against the allow-listed roots, and a UNC network path rejected, before the file is opened — identical to every other tool.
- `word/footnotes.xml` is parsed with the same hardened `lxml` parser as every other part this project reads.
- **Atomic write.** Only `word/footnotes.xml` is rewritten, via the existing `ooxml.atomic_write_part` (see [docs/security-model.md §3](../../../docs/security-model.md#3-atomic-write-contract)); `word/document.xml` and every other package part are never opened for writing by this tool.
- Every other declared footnote, the target footnote's `@w:id`, and every anchor in `word/document.xml` are left byte-for-byte unchanged.

## 7. Error Behavior

| Case | Behavior |
| --- | --- |
| `path` escapes all allowed roots / no allowed roots configured / UNC network path | Identical to every other tool. |
| File does not exist, is not a valid ZIP, exceeds the size limit, or is missing/has malformed `word/document.xml` | Identical to every other tool. |
| `word/footnotes.xml` is absent | Rejected: "footnote {footnote_id} not found: word/footnotes.xml is absent". |
| `word/footnotes.xml` is present but malformed XML | Rejected: "not a valid .docx file: malformed XML in word/footnotes.xml". |
| `footnote_id` is not declared in `word/footnotes.xml` | Rejected: "footnote {footnote_id} not found". |
| `footnote_id` is `"-1"` or `"0"` | Rejected: "cannot edit Word's reserved boilerplate footnote {footnote_id}". |
| `expected_content` is given and does not match the footnote's current content | Rejected: "stale footnote_id: the document no longer contains expected_content there - re-run get_footnotes". |
| `content` is empty | Not an error — an empty footnote is valid, if unusual. |

## 8. Test Coverage

Reference: `tests/test_footnote_edit.py` (functional and error/edge at the `edit_footnote_in_document` level), `tests/test_edit_footnote_tool.py` (contract, functional, error/edge at the MCP-protocol level), `tests/test_security.py` (path sandboxing, shared), `tests/integration/test_footnote_edit_consistency.py` (cross-tool round-trip against `get_footnotes`/`read_document`/`get_structure`).

- **Contract:** tool discoverable via `list_tools`; name, description, input schema, output schema, and version (`_meta`) match this spec.
- **Functional:** against `tests/fixtures/footnotes.docx`/`minimal.docx` — editing an existing footnote's content, both single-line and multi-line (paragraph count change, up and down), returns the correct `previous_content`, and the anchor/id/other footnotes are unaffected.
- **Error/edge:** path outside allowed roots; `word/footnotes.xml` absent; malformed `word/footnotes.xml`; unknown `footnote_id`; `footnote_id` `"-1"`/`"0"` rejected; `expected_content` mismatch (stale, rejected before any write); `expected_content` match (accepted); empty `content`; simulated crash mid-write leaves the original file byte-for-byte intact; XXE-crafted `word/footnotes.xml`.
- **Cross-tool consistency:** after `edit_footnote`, `get_footnotes` reports the new content at the same `id`/`paragraph_index`; `read_document`'s inline marker and `get_structure`'s footnote-anchor index for that id are unaffected by the content change.
