---

## Metadata

| Field | Value |
| --- | --- |
| **Tool name** | `add_footnote` |
| **Version** | `1.0.0` |
| **Type** | Write |
| **Status** | Implemented |

---

## 1. Purpose

Attach a new footnote to a paragraph in a `.docx` file's body: append a footnote-reference marker to the end of that paragraph's text, and add the footnote's content to `word/footnotes.xml`, wiring up `[Content_Types].xml` and `word/_rels/document.xml.rels` if the document has no footnotes yet — so the calling agent can add a footnote without knowing anything about `.docx`'s internal OOXML package structure.

## 2. Input Schema

| Parameter | Type | Required | Description / Value range |
| --- | --- | --- | --- |
| `path` | `str` | yes | Filesystem path to a `.docx` file. Same resolution and sandboxing rules as every other tool (see [specs/read_document.md §2](read_document.md#2-input-schema)). |
| `paragraph_index` | `int` | yes | 0-based index, among top-level body paragraphs, of the paragraph the new footnote is attached to. Same indexing as `get_structure`/`find_text`/`insert_paragraph`. |
| `content` | `str` | yes | The new footnote's text content. May be empty. A `"\n"` inside it starts a new paragraph within the footnote (see [Output Schema](#3-output-schema)). |

JSON Schema, as generated by the MCP SDK:

```json
{
  "type": "object",
  "properties": {
    "path": { "type": "string" },
    "paragraph_index": { "type": "integer" },
    "content": { "type": "string" }
  },
  "required": ["path", "paragraph_index", "content"]
}
```

## 3. Output Schema

Sketch:

```json
{ "footnote_id": "4" }
```

JSON Schema, generated from the `AddFootnoteResult` model:

```json
{
  "type": "object",
  "properties": {
    "footnote_id": { "type": "string" }
  },
  "required": ["footnote_id"]
}
```

Field semantics:

- **`footnote_id`** — the new footnote's `w:id`, as a string (matches `get_footnotes`'/`get_structure`'s existing `id: str` convention). **Always server-allocated, never caller-supplied**: one more than the largest integer-parseable, non-negative `w:footnote/@w:id` already declared in `word/footnotes.xml` (or `"1"` if that part is absent, or declares no such id) — the caller cannot request a specific id, matching [Roadmap.md, Phase 6](../../../Roadmap.md#phase-6--footnote-editing-add_footnote-edit_footnote)'s requirement to keep footnote ids "unique and valid" as a server responsibility. Use this returned id with `edit_footnote` or to interpret `get_footnotes`' output after the call.
- **Anchor placement**: the new `w:footnoteReference` is always appended as the **last run-level child** of the paragraph named by `paragraph_index` — never at an arbitrary character offset within it (see [Limitations](#5-limitations-non-goals) and [ADR-0007 §Decision.3](../../../docs/adr/0007-phase-6-footnote-edit-module-layout-and-multi-part-atomic-write.md) for why).
- **`word/footnotes.xml` content**: `content.split("\n")` becomes one `w:p` per line inside the new `<w:footnote>`; the first paragraph is prefixed with the standard auto-number reference run (`w:r/w:rPr/w:rStyle w:val="FootnoteReference"` + `w:footnoteRef`), matching every real footnote Word itself writes. This is the exact inverse of `get_footnotes`'/`specs/get_footnotes.md §3`'s `"\n".join(...)` content-reading convention, so a round-trip through `get_footnotes` after this call reproduces `content` verbatim.
- **Package wiring**: if `word/footnotes.xml` does not exist yet, it is created containing Word's two boilerplate footnotes (`w:id="-1"` separator, `w:id="0"` continuationSeparator — see [specs/get_footnotes.md §5](get_footnotes.md#5-limitations-non-goals)) plus the one new real footnote, together with a `[Content_Types].xml` `Override` and a `word/_rels/document.xml.rels` `Relationship` for it. All parts this call touches are written in a single atomic step (see [Formatting & Safety Guarantees](#6-formatting--safety-guarantees)).

## 4. Assumptions and Preconditions

- Same as every write tool: `path` resolves inside an allowed root, checked before the file is opened; the file is a valid ZIP containing at least `word/document.xml`.
- `[Content_Types].xml` is assumed present — it is OPC's own mandatory root part; its absence is treated as an invalid document (see [Error Behavior](#7-error-behavior)).
- `word/footnotes.xml` and `word/_rels/document.xml.rels` are **not** required to exist; both are created if missing (see [Output Schema](#3-output-schema)).

## 5. Limitations (Non-Goals)

- **No sub-paragraph placement.** The new footnote reference is always appended at the end of the target paragraph's text; there is no parameter to place it mid-sentence at a specific character offset. This is a deliberate choice, not an oversight: no read tool in this project — including `get_footnotes` itself — reports a footnote anchor more precisely than `paragraph_index`, so accepting a character offset on write would be a write-only precision no caller could ever confirm back through this project's own tools (see [ADR-0007](../../../docs/adr/0007-phase-6-footnote-edit-module-layout-and-multi-part-atomic-write.md)). A future MINOR version may add an optional offset parameter without breaking this default.
- **`paragraph_index` addresses only top-level body paragraphs**, identical to every other tool's scope — a footnote cannot be attached to a paragraph inside a table cell.
- **Endnotes are not supported.** Only `word/footnotes.xml`/`w:footnoteReference` — matching the rest of this tool surface's footnotes-only scope (see [specs/get_footnotes.md §5](get_footnotes.md#5-limitations-non-goals)).
- **Caller cannot choose the new footnote's id.** See [Output Schema](#3-output-schema); this is intentional, not a missing feature.
- **A Word table-of-contents or footnote-numbering field is not recomputed** by this tool — same documented boundary as `insert_paragraph`/`delete_paragraph` (see [Roadmap.md, Phase 5](../../../Roadmap.md#phase-5--paragraph-level-structure-edits-insert_paragraph-delete_paragraph)); Word recomputes visible footnote numbering itself when the file is next opened.

## 6. Formatting & Safety Guarantees

- `path` is resolved and validated against the allow-listed roots, and a UNC network path rejected, before the file is opened — identical to every other tool.
- Every internal XML part this tool reads (`word/document.xml`, `word/footnotes.xml` if present, `[Content_Types].xml`, `word/_rels/document.xml.rels` if present) is parsed with the same hardened `lxml` parser as every other tool (see [ADR-0001](../../../docs/adr/0001-ooxml-library-and-module-layout.md)).
- **Atomic, multi-part write.** All parts this call changes — always `word/document.xml` and `word/footnotes.xml`, plus `[Content_Types].xml` and `word/_rels/document.xml.rels` when `word/footnotes.xml` did not exist yet — are written together via `ooxml.atomic_write_parts` in a single temp-file-then-atomic-replace step (see [docs/security-model.md §3](../../../docs/security-model.md#3-atomic-write-contract)). A crash at any point before the final replace leaves the original file byte-for-byte intact and never leaves `word/document.xml` referencing a footnote `word/footnotes.xml` doesn't declare, or vice versa.
- No new archive-part name this tool writes is ever derived from caller input (`word/footnotes.xml`, `[Content_Types].xml`, and `word/_rels/document.xml.rels` are all fixed, hardcoded names) — this write path introduces no zip-slip/archive-injection surface.
- Everything the call doesn't touch — every other paragraph, every other run, every other declared footnote, every other package part — is left byte-for-byte unchanged.

## 7. Error Behavior

| Case | Behavior |
| --- | --- |
| `path` escapes all allowed roots / no allowed roots configured / UNC network path | Identical to every other tool. |
| File does not exist, is not a valid ZIP, exceeds the size limit, or is missing/has malformed `word/document.xml` | Identical to every other tool. |
| `paragraph_index` does not reference an existing top-level body paragraph | Rejected: "paragraph_index references a paragraph that does not exist". |
| `word/footnotes.xml` is present but malformed XML | Rejected: "not a valid .docx file: malformed XML in word/footnotes.xml". |
| `word/footnotes.xml` is absent and `[Content_Types].xml` is also absent | Rejected: "not a valid .docx file: missing [Content_Types].xml" — a `.docx` without it is not a valid OPC package at all. |
| `word/footnotes.xml` is absent and `word/_rels/document.xml.rels` is also absent | Not an error — a fresh `word/_rels/document.xml.rels` containing only the new footnotes relationship is created. |
| `[Content_Types].xml` already declares the footnotes `Override`, or `word/_rels/document.xml.rels` already declares a footnotes `Relationship`, despite `word/footnotes.xml` being absent | Not an error — the existing entry is reused, no duplicate is added. |
| `content` is empty | Not an error — a footnote with empty content is valid, if unusual. |

## 8. Test Coverage

Reference: `tests/test_footnote_edit.py` (functional and error/edge at the `add_footnote_to_document` level), `tests/test_add_footnote_tool.py` (contract, functional, error/edge at the MCP-protocol level), `tests/test_security.py` (path sandboxing, shared), `tests/integration/test_footnote_edit_consistency.py` (cross-tool round-trip against `get_footnotes`/`read_document`/`get_structure`).

- **Contract:** tool discoverable via `list_tools`; name, description, input schema, output schema, and version (`_meta`) match this spec.
- **Functional:** against `tests/fixtures/structured.docx` (no footnotes yet — proves the from-scratch `word/footnotes.xml`/`[Content_Types].xml`/`.rels` creation path) and `tests/fixtures/footnotes.docx`/`minimal.docx` (footnotes already present — proves the append path and correct id allocation, e.g. `"4"` after ids `1`-`3`); multi-line `content` producing multiple footnote paragraphs, round-tripped through `get_footnotes`.
- **Error/edge:** path outside allowed roots; out-of-range `paragraph_index`; malformed `word/footnotes.xml`; `[Content_Types].xml` missing entirely (hard error); `word/_rels/document.xml.rels` missing entirely (created fresh, synthetic archive); an existing but not-yet-referenced footnotes `Override`/`Relationship` (not duplicated); empty `content`; id allocation skips a non-numeric or out-of-order existing id without colliding; simulated crash mid-write leaves the original file byte-for-byte intact, in both the append-only and from-scratch cases; XXE-crafted `word/footnotes.xml` (external entity not resolved, reusing the shared hardened parser).
- **Cross-tool consistency:** after `add_footnote`, `get_footnotes` resolves the new id at the expected `paragraph_index` with the expected `content`; `read_document`'s inline markers and `get_structure`'s footnote-anchor index agree with it too.
